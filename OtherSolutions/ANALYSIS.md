### 7️⃣ FEATURE ENGINEERING (Подготовка признаков)

Это **очень важная часть**, где данные трансформируются в удобный для модели вид.

#### 7.1 Проблема в исходных данных

Исходные данные содержат **одну строку на одно товар за один месяц**. Это плохо для регрессии, потому что:
- Один товар может повторяться много раз (разные месяцы)
- Нужны независимые наблюдения, а не временной ряд

#### 7.2 Решение: Агрегирование по товарам

```python
cols_to_mean = ['product_id', 'month_year', 'comp1_diff', 'comp2_diff', 'comp3_diff',
                'fp1_diff', 'fp2_diff', 'fp3_diff', 'product_score', 'unit_price']
cols_to_sum = ['product_id', 'month_year', 'total_price', 'freight_price', 'customers']

products_mean = mean_df.groupby(by='product_id').mean()
products_sum = sum_df.groupby(by='product_id').sum()

products = pd.concat([products_sum, products_mean], axis=1, join='inner')
```

**Что происходит:**

1. **Для некоторых колонок используем СРЕДНЕЕ:**
   - `product_score` — берем среднюю оценку товара
   - `comp1_diff`, `comp2_diff`, `comp3_diff` — средняя разница в цене
   - `unit_price` — средняя цена товара
   
   **Зачем?** Потому что они относительно стабильны во времени

2. **Для других колонок используем СУММУ:**
   - `total_price` — общий объем продаж товара
   - `customers` — всего покупателей за весь период
   - `freight_price` — общие расходы на доставку
   
   **Зачем?** Потому что они кумулятивны и показывают "размер" товара

3. **Объединяем два фрейма:**
   ```
   [products_sum info] + [products_mean info] = final products table
   ```

**Результат:**
- Новый датасет с одной строкой на ТОВАР (не на товар-месяц)
- Каждая строка содержит все агрегирован информацию о товаре
- Готово для регрессионной модели

#### 7.3 Выбор признаков и целевой переменной

```python
X = products.drop(['product_id', 'unit_price'], axis=1)
y = products['unit_price']
```

**Запомните:** Они предсказывают `unit_price`, а **НЕ** `total_price`!

- **X (признаки):** Все кроме product_id и unit_price
- **y (целевая переменная):** unit_price

**Зачем убирают product_id?** Потому что это просто ID, не признак.  
**Зачем убирают unit_price из X?** Потому что это наша целевая переменная!

### 8️⃣ ПОСТРОЕНИЕ МОДЕЛИ (Model Building)

Это основная часть машинного обучения.

#### 8.1 Выбор алгоритма: Random Forest Regressor

```python
model = RandomForestRegressor(n_estimators=50, random_state=40)
model.fit(X, y)
y_pred = model.predict(X)
```

**Почему Random Forest, а не Linear Regression?**

| Критерий | Linear Regression | Random Forest |
|----------|------------------|---------------|
| **Сложность** | Простая | Сложная |
| **Нелинейные зависимости** | ❌ Плохо | ✅ Хорошо |
| **Мультиколлинеарность** | ❌ Чувствительна | ✅ Устойчива |
| **Интерпретируемость** | ✅ Легко | ⚠️ Сложнее |
| **Риск переобучения** | ✅ Низкий | ⚠️ Высокий |
| **Скорость** | ✅ Быстро | ⚠️ Медленнее |

**Почему Random Forest в этом случае выбран:**
- Цена товара зависит от множества факторов нелинейно
- Есть взаимодействия между признаками
- Random Forest лучше захватывает сложные зависимости

**Параметры:**
- `n_estimators=50` — используем 50 деревьев в лесу
- `random_state=40` — для воспроизводимости

#### 8.2 Оценка модели

```python
print(f"R2 score: {r2_score(y, y_pred)}")
print(f"Mean Absolute Error: {mean_absolute_error(y, y_pred)}")
```

**Интерпретация метрик:**

**R² score:**
- Показывает, какую долю вариации объясняет модель
- Диапазон: 0 до 1 (или даже отрицательный для плохой модели)
- 0.8 → хорошая модель, объясняет 80% вариации
- 0.95 → отличная модель, объясняет 95% вариации

**Mean Absolute Error (MAE):**
- Средняя абсолютная ошибка в денежных единицах
- Если MAE = 5, то в среднем предсказание ошибается на 5 рублей

### 9️⃣ MODEL EXPLAINABILITY (Интерпретируемость модели)

Это **самая инновационная часть** решения, которой часто пренебрегают!

#### 9.1 Зачем нужна интерпретируемость?

> "The job simply doesn't end with building a Machine Learning model that gives the best metrics. The main idea is to derive insights that can help a business or organization improve further."

**На практике:**
- 🎓 Статистик хорошо, но компания хочет **понять результаты**
- 💼 Бизнес-люди хотят знать: **какие признаки влияют на цену?**
- 🔍 Нужно выявлять ошибки и смещения в модели
- 📊 Нужна прозрачность для доверия к модели

#### 9.2 Permutation Importance (Важность признаков через перестановку)

```python
from eli5.sklearn import PermutationImportance
perm = PermutationImportance(model, random_state=1).fit(X, y)
eli5.show_weights(perm, feature_names = X.columns.tolist())
```

**Как это работает:**

1. Обучаем модель на исходных данных → получаем ошибку E₀
2. Для каждого признака:
   - Случайно перемешиваем значения признака в тестовом наборе
   - Вычисляем ошибку E₁
   - Важность = E₁ - E₀ (насколько ошибка выросла)
   - Большее значение = более важный признак

**Интерпретация:**
- Если признак важен → перемешивание сильно увеличит ошибку
- Если признак не важен → перемешивание почти не повлияет

**Практическое применение:** Отбросить признаки с низкой важностью

#### 9.3 SHAP Values (SHapley Additive exPlanations)

Это продвинутая техника теории игр для объяснения предсказаний.

**Идея:**
Для каждого предсказания вычисляем, как каждый признак повлиял на него:

```
Предсказание = Base Value + Contribution₁ + Contribution₂ + ... + Contributionₙ
```

**Пример:**
```
Unit Price Prediction = 50 (base value)
         + 10 (товар в дорогой категории)
         - 5 (конкуренты дешевле)
         + 3 (высокий рейтинг)
         = 58 (финальное предсказание)
```

#### 9.4 Анализ лучших и худших предсказаний

```python
largest_error = products[products['error'] == max(products['error'])]
smallest_error = products[products['error'] == min(products['error'])]
```

**Зачем:**
- Понять, почему модель ошибалась
- Выявить особые случаи
- Улучшить модель в проблемных областях

#### 9.5 SHAP Force Plot для худшего предсказания

```python
data_for_prediction = largest_error 
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(data_for_prediction)
shap.force_plot(explainer.expected_value[0], shap_values[0], data_for_prediction)
```

**Интерпретация (из ноутбука):**
> "The Competitor Differences were the major factors that led to such a high prediction. Among these, `comp_diff_1` had the highest impact. The competitor difference is high, and positive, which means that the competitors are selling for much lower and the total price is quite low. This is why the model predicts a high value, so that the product does not contribute to a loss for the retailer."

**Бизнес-смысл:**
- Если конкурент продает намного дешевле, то модель предсказывает ВЫСОКУЮ цену?
- Это кажется противоречием!
- Объяснение: **Высокая цена компенсирует убыток** (чтобы товар не продавался в убыток)

#### 9.6 SHAP Summary Plot

```python

```

**Что показывает:**
- Горизонтальный bar каждого признака
- **Длина bar** = средняя важность признака
- **Красный цвет слева** = признак снижает цену
- **Синий цвет справа** = признак повышает цену
- **Интенсивность цвета** = величина влияния

### Разница в целевой переменной
- **Они:** Предсказывают `unit_price` (цена за единицу)
- **Мы:** Предсказываем `total_price` (полная цена с доставкой)

**Это означает:**
- Их модель отвечает на: "Какую цену установить за товар?"
- Наша модель отвечает на: "Какой будет полная сумма для покупателя?"

### Выбор алгоритма
- **Они:** Random Forest (более сложный, но менее интерпретируемый)
- **Мы:** Linear Regression (простой, но легко интерпретировать)

**Это влияет на:**
- Точность прогноза (RF обычно лучше)
- Скорость обучения (LR быстрее)
- Понимание результатов (LR проще)

### Обработка данных
- **Они:** Агрегируют по товарам → создают новый датасет
- **Мы:** Используем данные как есть
