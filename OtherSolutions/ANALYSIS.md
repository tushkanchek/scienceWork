### 4️⃣ КОНКУРЕНТНЫЙ АНАЛИЗ (Competitive Comparison)

Это очень **практичный** фрагмент анализа.

#### 4.1 Разница в цене

```python
df['comp1_diff'] = df['unit_price'] - df['comp_1']
df['comp2_diff'] = df['unit_price'] - df['comp_2']
df['comp3_diff'] = df['unit_price'] - df['comp_3']
```

**Что означает:**
- `comp1_diff > 0` → цена выше цены конкурента; возможные последствия для спроса требуют отдельной проверки
- `comp1_diff < 0` → цена ниже цены конкурента; последствия для маржи из одной разницы не следуют
- `comp1_diff ≈ 0` → мы конкурентны!

**Визуализация по категориям:**
```python
for i in range(1,4):
    comp = f"comp{i}_diff"
    fig = px.bar(x=df['product_category_name'], y=df[comp],
                 title=f"Competitor {i} Price Difference per Unit")
```

Это показывает разницу цен по категориям, но само по себе не устанавливает, какая цена оптимальна.

#### 4.2 Разница в доставке

```python
df['fp1_diff'] = df['freight_price'] - df['fp1']
df['fp2_diff'] = df['freight_price'] - df['fp2']
df['fp3_diff'] = df['freight_price'] - df['fp3']
```

**Зачем это важно:**
- Возможная гипотеза: высокая стоимость доставки связана с меньшим числом клиентов; показанный код сам по себе этого не проверяет
- Конкурентный анализ доставки так же критичен, как анализ цены
- Итоговая сумма может учитывать цену товара, количество и доставку; точное тождество для `total_price` нельзя предполагать без проверки данных

**Бизнес-смысл:**
Эти разницы показывают расхождение с ценой конкурента. Они не определяют, насколько следует менять цену для максимизации спроса или прибыли.

### 7️⃣ FEATURE ENGINEERING (Подготовка признаков)

Это **очень важная часть**, где данные трансформируются в удобный для модели вид.

#### 7.1 Проблема в исходных данных

Исходные данные содержат повторные наблюдения товара по месяцам. Такие строки могут быть зависимыми, но это не делает регрессию автоматически неприменимой: можно моделировать повторные наблюдения с подходящей структурой ошибок. В рассматриваемом стороннем ноутбуке строки агрегируются по товару, что упрощает данные, но теряет временную информацию.

#### 7.2 Решение: Агрегирование по товарам

```python
cols_to_mean = ['product_id', 'month_year', 'comp1_diff', 'comp2_diff', 'comp3_diff',
                'fp1_diff', 'fp2_diff', 'fp3_diff', 'product_score', 'unit_price']
cols_to_sum = ['product_id', 'month_year', 'total_price', 'freight_price', 'customers']

products_mean = mean_df.groupby(by='product_id').mean()
products_sum = sum_df.groupby(by='product_id').sum()

products = pd.concat([products_sum, products_mean], axis=1, join='inner')
```

**Что происходит:**

1. **Для некоторых колонок используем СРЕДНЕЕ:**
   - `product_score` — берем среднюю оценку товара
   - `comp1_diff`, `comp2_diff`, `comp3_diff` — средняя разница в цене
   - `unit_price` — средняя цена товара
   
   **Зачем?** Потому что они относительно стабильны во времени

2. **Для других колонок используем СУММУ:**
   - `total_price` — общий объем продаж товара
   - `customers` — всего покупателей за весь период
   - `freight_price` — общие расходы на доставку
   
   **Зачем?** Потому что они кумулятивны и показывают "размер" товара

3. **Объединяем два фрейма:**
   ```
   [products_sum info] + [products_mean info] = final products table
   ```

**Результат:**
- Новый датасет с одной строкой на ТОВАР (не на товар-месяц)
- Каждая строка содержит все агрегирован информацию о товаре
- Готово для регрессионной модели

#### 7.3 Выбор признаков и целевой переменной

```python
X = products.drop(['product_id', 'unit_price'], axis=1)
y = products['unit_price']
```

**Запомните:** Они предсказывают `unit_price`, а **НЕ** `total_price`!

- **X (признаки):** Все кроме product_id и unit_price
- **y (целевая переменная):** unit_price

**Зачем убирают product_id?** Потому что это просто ID, не признак.  
**Зачем убирают unit_price из X?** Потому что это наша целевая переменная!

**Важное ограничение:** признаки `comp1_diff`, `comp2_diff` и `comp3_diff` ранее рассчитаны как разность `unit_price` и цены конкурента, а затем остаются в `X`. Значит, предикторы содержат информацию о целевой переменной (утечка целевой переменной).

### 8️⃣ ПОСТРОЕНИЕ МОДЕЛИ (Model Building)

Это основная часть машинного обучения.

#### 8.1 Выбор алгоритма: Random Forest Regressor

```python
model = RandomForestRegressor(n_estimators=50, random_state=40)
model.fit(X, y)
y_pred = model.predict(X)
```

Предсказания и метрики рассчитываются на тех же строках, на которых модель обучалась; разделения на обучающую и тестовую выборки в этом фрагменте нет. Поэтому приведённые метрики характеризуют подгонку на обучающих данных, а не качество на новых наблюдениях. Вместе с утечкой целевой переменной это не позволяет делать надёжные выводы о прогностической способности.

**Почему Random Forest, а не Linear Regression?**

| Критерий | Linear Regression | Random Forest |
|----------|------------------|---------------|
| **Сложность** | Простая | Сложная |
| **Нелинейные зависимости** | ❌ Плохо | ✅ Хорошо |
| **Мультиколлинеарность** | ❌ Чувствительна | ✅ Устойчива |
| **Интерпретируемость** | ✅ Легко | ⚠️ Сложнее |
| **Риск переобучения** | ✅ Низкий | ⚠️ Высокий |
| **Скорость** | ✅ Быстро | ⚠️ Медленнее |

**Что может дать Random Forest:** он способен описывать нелинейности и взаимодействия, но не гарантирует лучшего качества без корректной проверки на данных, не участвовавших в обучении. В этом ноутбуке такое сравнение не выполнено.

**Параметры:**
- `n_estimators=50` — используем 50 деревьев в лесу
- `random_state=40` — для воспроизводимости

#### 8.2 Оценка модели

```python
print(f"R2 score: {r2_score(y, y_pred)}")
print(f"Mean Absolute Error: {mean_absolute_error(y, y_pred)}")
```

**Интерпретация метрик:**

**R² score:**
- Показывает, какую долю вариации объясняет модель
- Диапазон: 0 до 1 (или даже отрицательный для плохой модели)
- универсальной границы, при которой значение автоматически считается хорошим или отличным, нет

**Mean Absolute Error (MAE):**
- Средняя абсолютная ошибка в единицах целевой переменной
- Если MAE = 5, средняя абсолютная ошибка равна пяти единицам `unit_price`; валюта набора данных здесь не установлена

### 9️⃣ MODEL EXPLAINABILITY (Интерпретируемость модели)

Это **самая инновационная часть** решения, которой часто пренебрегают!

#### 9.1 Зачем нужна интерпретируемость?

> "The job simply doesn't end with building a Machine Learning model that gives the best metrics. The main idea is to derive insights that can help a business or organization improve further."

**Возможные задачи интерпретации:**
- 🎓 Статистик хорошо, но компания хочет **понять результаты**
- 💼 Для обсуждения модели полезно понимать, какие признаки связаны с её предсказаниями; это не доказывает причинное влияние на цену
- 🔍 Нужно выявлять ошибки и смещения в модели
- 📊 Нужна прозрачность для доверия к модели

#### 9.2 Permutation Importance (Важность признаков через перестановку)

```python
from eli5.sklearn import PermutationImportance
perm = PermutationImportance(model, random_state=1).fit(X, y)
eli5.show_weights(perm, feature_names = X.columns.tolist())
```

В этом ноутбуке перестановочная важность также считается на обучающих данных, а некоторые признаки построены из `unit_price`. Поэтому её нельзя трактовать как надёжную важность признаков для новых данных.

**Как это работает:**

1. Обучаем модель на исходных данных → получаем ошибку E₀
2. Для каждого признака:
   - Случайно перемешиваем значения признака в тестовом наборе
   - Вычисляем ошибку E₁
   - Важность = E₁ - E₀ (насколько ошибка выросла)
   - Большее значение = более важный признак

**Интерпретация:**
- Если признак важен → перемешивание сильно увеличит ошибку
- Если признак не важен → перемешивание почти не повлияет

**Практическое применение:** Отбросить признаки с низкой важностью

#### 9.3 SHAP Values (SHapley Additive exPlanations)

Это продвинутая техника теории игр для объяснения предсказаний.

**Идея:**
Для каждого предсказания вычисляется вклад признака в выход модели. Это объяснение поведения модели, а не оценка причинного влияния признака на цену:

```
Предсказание = Base Value + Contribution₁ + Contribution₂ + ... + Contributionₙ
```

**Пример:**
```
Unit Price Prediction = 50 (base value)
         + 10 (товар в дорогой категории)
         - 5 (конкуренты дешевле)
         + 3 (высокий рейтинг)
         = 58 (финальное предсказание)
```

#### 9.4 Анализ лучших и худших предсказаний

```python
largest_error = products[products['error'] == max(products['error'])]
smallest_error = products[products['error'] == min(products['error'])]
```

**Зачем:**
- Понять, почему модель ошибалась
- Выявить особые случаи
- Улучшить модель в проблемных областях

#### 9.5 SHAP Force Plot для худшего предсказания

```python
data_for_prediction = largest_error 
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(data_for_prediction)
shap.force_plot(explainer.expected_value[0], shap_values[0], data_for_prediction)
```

**Интерпретация (из ноутбука):**
> "The Competitor Differences were the major factors that led to such a high prediction. Among these, `comp_diff_1` had the highest impact. The competitor difference is high, and positive, which means that the competitors are selling for much lower and the total price is quite low. This is why the model predicts a high value, so that the product does not contribute to a loss for the retailer."

**Бизнес-смысл:**
- Если конкурент продает намного дешевле, то модель предсказывает ВЫСОКУЮ цену?
- Это кажется противоречием!
- Объяснение: **Высокая цена компенсирует убыток** (чтобы товар не продавался в убыток)

#### 9.6 SHAP Summary Plot

```python
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X)
shap.summary_plot(shap_values, X)
```

**Что показывает:**
- Горизонтальный bar каждого признака
- **Длина bar** = средняя важность признака
- **Красный цвет слева** = признак снижает цену
- **Синий цвет справа** = признак повышает цену
- **Интенсивность цвета** = величина влияния

> "The ultimate aim of optimizing retail prices is to charge a price that helps you make the most money and attracts enough customers to buy your products. It involves using data and pricing strategies to find the right price that maximizes your sales and profits while keeping customers happy."

**Что фактически делает код:**
- обучает Random Forest на агрегированных значениях `unit_price`;
- строит предсказания на тех же данных, что использовались для обучения;
- рассчитывает permutation importance и SHAP-объяснения предсказаний.

Код не оценивает причинное влияние признаков и не находит цену, оптимальную по прибыли. Из-за признаков, построенных с использованием `unit_price`, и отсутствия тестовой выборки качество обобщения не проверено.

## 💡 ЧТО МОЖНО ПОЗАИМСТВОВАТЬ ДЛЯ НАШЕГО ПРОЕКТА

### 1️⃣ Конкурентный анализ
Создать разницы в ценах и доставках конкурентов, чтобы понять позиционирование.

### 2️⃣ Сравнение алгоритмов
Это отдельное будущее исследование: сначала нужно исключить признаки, построенные из целевой переменной, и оценивать модели на отложенных данных. В текущую курсовую сравнение не входит.

### 3️⃣ Model Explainability
Добавить SHAP анализ для понимания того, какие факторы влияют на цену.

### 4️⃣ Анализ по дням недели / сезонности
Более подробно изучить временные зависимости.

### 5️⃣ Агрегирование данных для регрессии
Если есть повторяющиеся товары, рассмотреть агрегирование.

## ⚠️ ОТЛИЧИЯ И НАБЛЮДЕНИЯ

### Разница в задаче
- **Сторонний ноутбук:** предсказывает `unit_price` на агрегированных по товару данных.
- **Текущая курсовая:** анализирует статистические связи с `total_price` и не строит прогнозов.

В используемом файле `total_price` приблизительно соответствует `unit_price × qty`; `freight_price` хранится отдельным столбцом. Поэтому называть `total_price` «полной ценой с доставкой» нельзя.

### Выбор алгоритма
- **Они:** Random Forest (более сложный, но менее интерпретируемый)
- **Мы:** Linear Regression (простой, но легко интерпретировать)

Качество прогнозов этих моделей напрямую не сравнивается: текущая курсовая решает задачу статистического вывода, а сторонний ноутбук оценивает прогноз на обучающих строках с утечкой целевой переменной.

### Обработка данных
- **Они:** Агрегируют по товарам → создают новый датасет
- **Мы:** Используем данные как есть
